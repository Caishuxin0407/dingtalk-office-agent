# 钉钉办公智能助手：项目技术说明

## 1. 项目目标

本项目实现一个可在钉钉群内交互的办公自动化助手。用户通过自然语言提出问题，机器人能够查询本地公告、本人报销记录和本人待办事项，并支持创建和完成待办。

项目重点不只是“调用大模型”，还包括：

- 将自然语言请求路由到明确的业务工具；
- 通过钉钉发送者身份识别当前用户；
- 限制个人数据只能由本人查询；
- 使用自动化测试验证身份隔离和访问控制逻辑。

## 2. 整体工作流

```text
用户在钉钉群 @机器人发送消息
        ↓
DingTalk Stream 长连接接收消息
        ↓
dingtalk_bot.py 获取消息文本和 sender_id
        ↓
从 DINGTALK_USER_MAP 映射内部员工身份
        ↓
agent.py 写入 ContextVar 请求身份
        ↓
LangChain Agent 判断意图并调用工具
        ↓
公告 / 报销 / 待办工具访问 SQLite
        ↓
生成回答并通过钉钉机器人回复群消息
```

## 3. 模块职责

### 3.1 `app/dingtalk_bot.py`

钉钉 Stream 机器人入口。

主要职责：

- 使用钉钉应用凭证建立 Stream 长连接；
- 接收群内文本消息；
- 获取 `sender_id`；
- 调用 `get_employee_from_sender()` 将钉钉发送者映射为内部员工；
- 未映射账号直接拒绝个人数据访问；
- 调用 Agent 并将最终文本回复发送到钉钉群。

### 3.2 `app/agent.py`

大模型 Agent 和工具路由层。

主要职责：

- 通过 `ChatOpenAI` 调用 OpenAI 模型；
- 注册公告、报销、待办等工具；
- 使用系统提示词约束工具调用规则；
- 在调用 Agent 前设置当前员工上下文；
- 在 `finally` 中重置上下文，避免不同用户请求相互污染。

### 3.3 `app/user_context.py`

请求级身份上下文模块。

核心对象是 `ContextVar`。它用于保存“当前这一次请求属于哪个员工”。

使用 ContextVar 的原因：

- 普通全局变量可能被并发请求覆盖；
- ContextVar 可以让不同请求拥有独立身份；
- 请求结束后通过 token 恢复原值，降低身份串用风险。

### 3.4 `app/database.py`

SQLite 数据模型和数据访问层。

当前主要数据表：

| 表名 | 用途 |
| --- | --- |
| `announcements` | 本地公告数据 |
| `expense_claims` | 演示报销单数据 |
| `todo_items` | 本地待办数据 |

待办数据包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `owner` | 待办所属员工 |
| `title` | 待办标题 |
| `status` | 待办状态，例如待办、已完成 |
| `due_at` | 截止时间，可为空 |
| `created_at` | 创建时间 |

### 3.5 `app/tools/`

这里存放 Agent 可调用的业务工具。

- `announcements.py`：公告关键词检索；
- `expenses.py`：查询当前员工的报销记录；
- `todos.py`：查询、新增和完成当前员工的待办。

工具层不负责理解复杂业务流程，而是把数据库函数封装为可被 Agent 调用的明确能力。

## 4. 身份隔离设计

个人报销和待办属于敏感数据，因此不能仅依赖用户在自然语言中自报姓名。

当前实现方式：

1. 钉钉消息携带 `sender_id`；
2. 程序从 `.env` 的 `DINGTALK_USER_MAP` 读取映射；
3. 映射成功后得到内部员工名；
4. Agent 将员工名写入 `ContextVar`；
5. 待办和报销工具只读取 `get_current_employee()` 返回的员工身份；
6. 数据库查询使用该员工身份作为过滤条件；
7. 未映射账号不能调用个人数据工具。

例如，当前用户身份为“蔡淑欣”时：

```text
query_todos(owner="蔡淑欣")
query_expense_claims(employee="蔡淑欣")
```

因此不会返回其他员工的演示数据。

## 5. 已实现功能

### 5.1 公告查询

用户示例：

```text
@机器人 报销材料什么时候提交？
```

Agent 调用公告检索工具，在本地公告表中检索“报销”等关键词，并根据查询结果回答。

### 5.2 本人报销查询

用户示例：

```text
@机器人 我审核中的报销单有几条，金额是多少？
```

机器人仅查询当前钉钉映射身份对应的报销单，并汇总数量、金额和状态。

### 5.3 本人待办管理

用户示例：

```text
@机器人 我有哪些待办？
@机器人 新增待办：提交阶段性项目总结，截止时间是 2026-09-02T10:00:00
@机器人 将整理本周项目周报标记为已完成
```

机器人分别调用待办查询、创建和完成工具，并将结果回传至钉钉群。

## 6. 自动化测试

运行全部测试：

```bash
python -m pytest -q
```
测试会通过 `tests/conftest.py` 在系统临时目录创建独立 SQLite 数据库；每条测试运行前重置数据，并在测试会话结束后自动清理，因此不会修改项目内的 `office_agent.db` 演示数据。

当前共有 9 项 pytest 测试，覆盖：

- 身份上下文的设置、嵌套和清理；
- 无身份访问待办时抛出异常；
- 无身份访问报销时返回拒绝信息；
- 蔡淑欣身份无法读取林晓的待办；
- 蔡淑欣身份无法读取林晓的报销；
- 合法钉钉发送者映射；
- 未知发送者拒绝；
- 非法 JSON 映射配置拒绝。

## 7. 启动方式

终端一：启动本地 FastAPI 服务。

```bash
source .venv/bin/activate
uvicorn app.main:app --reload
```

终端二：启动钉钉 Stream 机器人。

```bash
source .venv/bin/activate
python -m app.dingtalk_bot
```

机器人运行时，第二个终端保持打开是正常现象：它在持续等待钉钉推送的新消息。

## 8. 请求审计与指标统计

每次 Agent 请求都会记录以下信息：

- 请求是否成功；
- 响应耗时；
- 当前员工身份；
- 错误摘要（如有）。

日志仅记录用户消息长度，不保存完整提问内容，避免将群聊中的原始文本写入本地日志。日志文件位于 `logs/agent.log`，且已被 `.gitignore` 排除，不会被提交到 GitHub。

可通过以下命令查看本地聚合指标：

```bash
python -m app.metrics_report
```

该脚本输出请求总数、成功请求数、成功率和平均响应时间。当前统计只反映本地已记录的演示请求，不应将少量测试请求的成功率视为生产稳定性指标。

## 9. 当前边界

本项目当前是可运行的本地演示版本：

- 数据存储为 SQLite 演示数据；
- 身份映射是 `.env` 中维护的本地白名单；
- 未接入真实企业业务数据库；
- 未接入真实钉钉待办 API；
- 未实现生产级审计、监控和权限管理后台。

因此，项目不应描述为“已接入企业生产系统”，而应准确描述为：

> 已完成基于钉钉 Stream 的群端交互闭环，并实现本地公告、本人报销与本人待办的工具调用和身份隔离验证。

## 10. 后续迭代方向

1. 为待办补充截止时间更新、撤销完成和筛选排序功能。
2. 扩展为工具级调用指标，例如分别统计公告、报销和待办工具的调用成功率。
3. 在获得最小必要权限后，对接真实钉钉待办 API 或企业业务系统 API。
4. 用企业统一身份服务替代本地 `.env` 白名单映射。
